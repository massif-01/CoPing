# CoPing 兼容性维护：升级与回退

日期：2026-09-24。适用于 0.2.0。用户已自行完成一次测试包升级、Hook 重新信任和 ntfy 手机收件；其他升级条件仍见下文。助手没有修改真实 Codex 配置或信任记录。

## 升级步骤

1. 保留旧 CoPing App。先退出旧 App，再替换 App；安装 0.2.0 后按以下步骤重新确认连接。
2. 打开 Codex 设置，核对宿主与 Codex Home。App bundle ID 必须是已知 OpenAI 身份且内置引擎可执行；不要求另装 CLI。显式选择只在断开状态允许，选择本身不安装 Hook。
3. 默认使用 SessionStart、Stop、PermissionRequest，以及旧提问配对的 PreToolUse/PostToolUse。Post 的 answers 仅取消对应原生调用，不表示用户亲自回答。未知旧宿主是否支持这个最小契约须先隔离验证，不能无条件发布。当前检测到的 0.155.0-alpha.16.4 没有经过真实扩展事件验证，**不要仅凭版本较新就勾选扩展提问**。
4. 若已在隔离环境证明目标宿主支持本文参考的新旧提问名称、调用 ID、PostToolUse 响应形状，才勾选对应选项。配置界面中的勾选是维护者对已取得证据的选择，不是自动能力探测或通过认证。
5. 点击连接/修复：复制临时 Helper、验证签名，然后替换已安装副本；更新本 Home 中精确属于 CoPing 的 handlers。定义变化时打开正常 `/hooks` 审核入口，不绕过信任或组织策略。审核命令使用选择的引擎及同一个 `CODEX_HOME`。
6. 用无敏感内容的专用任务取得真实 Hook。配置写入、人工信任、Hook 到达、审批精确分类和手机收件是不同证据。新的“已验证”标记绑定 source、hooks 文件、Helper 内容和宿主 build；旧 boolean 标记不沿用。
7. 逐项执行兼容性报告中的实机验收。完成前不要以本地自测发布“全版本兼容”。

## 配置保留与幂等

只操作所选 Home 的 hooks.json。根字段、其他事件、第三方 groups/handlers 原样保留；未知/损坏结构直接报错。CoPing 自己的偏好、Bark 地址/密钥、ntfy Topic、语言、历史仍在原有位置，不迁入 Codex Home。

只认当前 Helper 的精确 command（含 0.1.6 旧引号拼写），不按字符串包含关系删除。未知旧安装路径不自动认领，须核实历史安装记录后人工处理。重复安装不更改文件，不新建备份；相同 Helper 不重新替换；相同且已验证的连接不再次打开信任审核。

配置变更保存 `hooks.json.coping-backup-<time>-<uuid>`，校验 JSON，使用 NSFileCoordinator、写前内容比较和原子替换。可检测测试中的并发编辑。**不声称能对绕过文件协调、恰好在最后一次比较与 rename 之间写入的任意程序提供原子 compare-and-swap**；迁移时应关闭 hooks.json 编辑器，此极窄竞争仍待处理。

## 失败恢复

- Helper 缺失/签名失败：不删除旧 Helper；界面显示错误。临时副本清理。
- 成功替换 Helper 时保留同目录 `CoPingHook.previous-<uuid>`。Hook 配置随后失败时，新 Helper 和该备份仍在，连接进入错误状态，不声称接通；修复原因后再次连接。
- 配置冲突：不覆盖新编辑，重新读取后重试。不要把旧 hooks.json 备份整份覆盖回去，尤其是在用户后续编辑之后。
- 回退 Helper：退出 App，将经过核对的 previous 副本恢复到 `bin/CoPingHook`，确认权限和签名，再恢复配套 App。此恢复未在用户真实安装目录执行。
- 回退配置：比较当前文件与备份，仅恢复 CoPing 自己的 handler。保留后来的第三方修改，再走正常 Hook 审核。卸载也只移除精确的自有项。

## 混合版本

CoPing IPC 仍为 1，已有 eventType raw value 不变；新元数据可选。新 App 能解码旧 Helper，并在接收端根据旧 wire 的创建时间与作用域生成稳定 ID：同一 wire 重放去重，不同创建时间仍独立。新 Helper 每次无 call 的 Hook 执行只生成一次 UUID 并沿传输保留。这不保证识别上游的重复执行；完全相同的旧字段/时间无法区分新的调用。

旧 Helper 没有 source token，不能验证当前来源；不从所选 Home 查询这些事件的标题。应安装新 Helper 后重新验证。旧 App + 新 Helper 的新增 phase **不受支持**：旧 App 会忽略 phase；必须先退出旧 App，并将 App、Helper、订阅作为一组升级/回退。

## 通知语义

未知模式为“有问题待查看”；没有新的阻塞证据就不说“任务暂停”。新异步问题只有 accepted 才发一次通知，accepted 不是回答。旧工具结构化 answers 只表示等待结束，可能是人工、自动解决或取消；不区分猜测原因。缺少可靠失败/Interrupt/来源契约的情况仍受限。

Stop 仍保留旧版完成候选投递，可能提前、把上游再次执行 Hook 当成新候选或把未知来源当成完成；没有宣称可靠根终态适配完成。Stop 不再批量清掉问题/审批。暂停、断开、切换来源会清理未发工作，不能撤回已交给远端的请求。恢复通知时，若仍启用“仅人工介入”且连接可用，则重启监控；当前有效 snapshot 等待可提醒，已结束历史不重新排队。
